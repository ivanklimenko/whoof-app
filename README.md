# Whoof — прототип для разработчика

Срез от 23 сентября 2026. Чёрно-белая версия с мокапом iPhone, исходная ветка `codex/iphone-mockup`, коммит `113c010`. Это самостоятельная копия проекта: доступ к Codex или исходному компьютеру не нужен. Переключатель вверху также позволяет посмотреть Pixel 10. Версия без рамки в этот архив не включена.

## Запуск

Требуется Node.js 22.12+ (проверено на 24.12.0) и npm. Выполнять в папке с этим README:

```sh
npm ci
npm run dev -- --port 4176 --strictPort
```

Открыть http://localhost:4176/ . Если порт занят, выберите другой. Для первого `npm ci` нужен доступ к npm registry. API-ключи и `.env` не нужны.

## Сборка и проверки

```sh
npm run build
npm run test:sites
```

Статические файлы: `dist/client/`. Сборка также готовит необязательный адаптер статического Cloudflare Worker в `dist/server/`. Она ничего не публикует.

Просмотр production-сборки:

```sh
npx vite preview --host 127.0.0.1 --port 4177
```

Для существующих браузерных тестов механики эмулятора:

```sh
npx playwright install chromium
MOBILE_RUNTIME_TEST_PORT=4180 npm run test:runtime
```

В PowerShell переменную задайте отдельно: `$env:MOBILE_RUNTIME_TEST_PORT="4180"`. Порт 4180 должен быть свободен. Эти тесты проверяют оболочку устройства; это не полное покрытие пользовательских сценариев Whoof.

## Где что находится

- `src/Prototype.tsx` — экраны, демонстрационные данные, график, линейка времени, инсайты, медкарта и обработчики действий.
- `src/prototype.css` — оформление Whoof.
- `src/App.tsx`, `src/main.tsx` — подключение приложения к оболочке.
- `src/mobile/` — мокап устройства, прокрутка, карусель, клавиатура, нижние панели. Контракт компонентов: `src/mobile/COMPONENTS.md`.
- `src/styles.css` — стили оболочки устройства.
- `public/assets/whoof/` — собака и карта; остальные каталоги assets нужны для мокапов и клавиатуры.
- `tests/` и `playwright.config.ts` — тесты оболочки и статического Worker.
- `scripts/`, `mobile-runtime.lock.json` — проверка целостности оболочки и подготовка сборки.
- `.openai/hosting.json`, `worker/index.js` — технические входные файлы существующей сборки. В конфигурации нет аккаунта, ключей или подключения к облачному проекту; удаление файла сломает текущую команду build.

Команды dev/build сначала проверяют хеши 28 файлов оболочки. UI приложения меняйте в Prototype.tsx/prototype.css. Если намеренно меняете саму оболочку, сначала проверьте её поведение, затем обновите контрольные суммы командой `npm run update:runtime-lock`.

## Что уже можно посмотреть

Главная: состояние питомца, карта дня, календарь, выбор 15-минутного отрезка линейкой или графиком, точки инсайтов и итоги дня. Метрики: плитки и подробности. Прогулки: карта, приглашения, запись и история. Профиль: данные питомца и медкарта. AI: интерфейс диалога.

## Границы текущей реализации

Это фронтенд-прототип на React 19, TypeScript и Vite 8. Backend, авторизация, BLE-подключение и получение реальной телеметрии ещё не реализованы. Ответы AI заранее заданы; карта — изображение; геопозиции, приглашения и дистанции условные. Состояние интерфейса преимущественно живёт в памяти до перезагрузки.

Медкарта действительно принимает файлы и хранит их локально в IndexedDB текущего браузера и адреса. Есть список, просмотр изображений/PDF, скачивание и удаление. Поддерживаются изображения, PDF, DOC/DOCX, RTF, TXT до 20 МБ на файл. Файлы пользователя в архив не входят. Предпросмотр некоторых форматов зависит от браузера. Для загрузки в этой версии нужен localhost или HTTPS: используется `crypto.randomUUID()`, недоступный на обычном HTTP-адресе в локальной сети.

Дата выбирается относительно локального дня браузера. Данные за сегодня — фиксированный сценарий до 14:30, за прошлые дни — условные сутки. Это не поток актуальных показаний.

## Важное уточнение по устройству

Сейчас аппаратная часть содержит акселерометр и гироскоп; микрофон планируется позже. Пульс, дыхание и температура, оставшиеся в UI, — прежние условные значения, а не доступные измерения устройства. Их нельзя переносить в требования к реальной телеметрии.

Обсуждённый, но ещё не реализованный вариант замены блока под графиком: «В движении» и «Интенсивная активность» за выбранный отрезок. Алгоритм оценки интенсивности и длительности требует определения и проверки на реальном устройстве.

Инсайты про встречу с другом или игру — иллюстрация сценария. Датчики движения сами по себе не подтверждают конкретную встречу или эмоциональное состояние. Формулировки и доказательную базу инсайтов нужно согласовать при интеграции реальных данных.
