# Whoof — прототип мобильного приложения

Кликабельный фронтенд-прототип нового приложения Whoof. Срез от 25 сентября 2026: визуальная редакция `design_v1` (ветка `design_v1`, основана на `f9257c1`). Предыдущий чёрно-белый срез от 23 сентября (`codex/iphone-mockup` @ `113c010`) — первый коммит этого репозитория.

Онлайн: **https://ivanklimenko.github.io/whoof-app/** — лучше открывать с телефона.

## Две версии

- **Без рамки (по умолчанию).** `index.html` → `src/native-main.tsx`. Приложение на весь экран, использует настоящую клавиатуру, прокрутку и safe areas браузера. Эта версия публикуется на Pages. Проверено на ширине 360, 390 и 430 px.
- **В рамке iPhone / Pixel 10.** `src/main.tsx` → `src/App.tsx` с симулятором устройства из `src/mobile/`. Код сохранён, но сейчас не подключён к `index.html`: чтобы посмотреть, временно поменяйте в нём скрипт на `/src/main.tsx`.

## Запуск

Нужны Node.js 22.12+ и npm.

```sh
npm ci
npm run dev -- --port 4176 --strictPort
```

Открыть http://localhost:4176/ . API-ключи и `.env` не нужны.

Для проверки на телефоне в той же Wi-Fi-сети запустите с `--host 0.0.0.0` и откройте прототип по LAN-адресу Mac, а не по localhost: QR-код приглашения строится от текущего адреса страницы.

## Сборка и проверки

```sh
npm run build
npm run test:sites
```

`npm run build` проверяет TypeScript, собирает статику в `dist/client/` и готовит необязательный адаптер Cloudflare Worker в `dist/server/`. Ничего не публикует.

Браузерные тесты оболочки устройства:

```sh
npx playwright install chromium
MOBILE_RUNTIME_TEST_PORT=4180 npm run test:runtime
```

`qa/check.mjs` — прогон основных сценариев версии без рамки со снимками экранов в `qa/`. Адрес задаётся через `QA_URL` (по умолчанию `http://localhost:4178/`).

## Публикация

Каждый пуш в `main` собирается и выкладывается на GitHub Pages workflow-ом `.github/workflows/pages.yml`. Сайт живёт в подкаталоге `/whoof-app/`, поэтому workflow вызывает `vite build --base /<имя репозитория>/`. Пути к картинкам в коде приложения строятся от `import.meta.env.BASE_URL`, а не от `/`.

## Где что находится

- `src/Prototype.tsx`, `src/prototype.css` — экраны, демо-данные, графики, инсайты, медкарта, приглашения. Здесь весь UI приложения; финальная секция стилей содержит токены design_v1.
- `src/native-main.tsx`, `src/native/` — обвязка версии без рамки.
- `src/main.tsx`, `src/App.tsx`, `src/styles.css`, `src/mobile/` — симулятор устройства. Контракт компонентов: `src/mobile/COMPONENTS.md`.
- `public/assets/whoof/` — собака и карта; остальные каталоги assets нужны симулятору.
- `tests/`, `playwright.config.ts` — тесты оболочки и статического Worker.
- `scripts/`, `mobile-runtime.lock.json` — проверка целостности оболочки и подготовка сборки.
- `.openai/hosting.json`, `worker/index.js` — входные файлы сборки под Sites; аккаунтов и ключей нет, без них `npm run build` падает.
- `AGENTS.md` — инструкции для ИИ-агента (Codex), `DESIGN_V1.md`, `design-qa.md`, `PHONE_PREVIEW.md` — заметки по редизайну и проверке.

### Защищённые файлы

Команды dev и build сначала сверяют хеши 28 файлов оболочки (в том числе `vite.config.ts`, `src/mobile/`, `src/App.tsx`, `src/main.tsx`). Если какой-то из них изменён, сборка останавливается. UI меняйте в `Prototype.tsx` / `prototype.css`. Если оболочку нужно поменять намеренно — проверьте поведение и обновите суммы командой `npm run update:runtime-lock`.

## Что можно посмотреть

Главная: состояние питомца, карта дня, календарь, выбор 15-минутного отрезка, точки инсайтов, итоги дня. Метрики: плитки и подробности. Прогулки: карта, запись, пауза, история. Настройки: профиль питомца, медкарта, доступ второму владельцу с QR-приглашением. AI: интерфейс диалога.

## Границы прототипа

React 19, TypeScript, Vite 8, только фронтенд. Backend, авторизации, BLE и реальной телеметрии нет. Ответы AI заданы заранее, карта — картинка, геопозиции, приглашения и дистанции условные. Состояние живёт в памяти до перезагрузки.

Медкарта по-настоящему принимает файлы (изображения, PDF, DOC/DOCX, RTF, TXT до 20 МБ) и хранит их в IndexedDB текущего браузера. Нужен localhost или HTTPS: используется `crypto.randomUUID()`.

Данные за сегодня — фиксированный сценарий до 14:30, за прошлые дни — условные сутки.

## Про устройство

В браслете сейчас акселерометр и гироскоп, микрофон планируется. Пульс, дыхание и температура в UI — условные значения, в требования к телеметрии их переносить нельзя. Инсайты про встречу с другом или игру — иллюстрация: датчики движения сами по себе такое не подтверждают.
